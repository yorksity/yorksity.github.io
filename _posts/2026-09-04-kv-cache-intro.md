在大语言模型（LLM）的推理过程中，有一个反复被提及的名词——**KV Cache**。它是几乎每一个推理引擎（vLLM、TensorRT-LLM 等）都绕不开的核心优化。本文从注意力机制出发，讲清楚 KV Cache 是什么、为什么需要它，以及它带来的收益与代价。

## 为什么需要 KV Cache

要理解 KV Cache，先回到 Transformer 的自注意力机制。对于给定的查询 `Q`、键 `K`、值 `V`，注意力计算为：

```
Attention(Q, K, V) = softmax(QK^T / √d_k) V
```

在**自回归生成**时，模型每次只生成一个 token，然后把新 token 拼到输入序列末尾，进入下一轮。问题是：每次生成一个新的 token，都要对所有历史 token 重新计算一遍 `K` 和 `V`，再做一次完整的注意力。

以一个长度为 `n` 的序列为例：

```
第 1 步：计算 token_1 的 K、V，做 1 次注意力
第 2 步：重新计算 token_1、token_2 的 K、V，做 2 次注意力
第 3 步：重新计算 token_1、token_2、token_3 的 K、V，做 3 次注意力
...
```

每一步都重复计算了之前已经算过的 `K` 和 `V`，计算量随序列长度呈平方级增长，大量算力被白白浪费。

## 核心思想：缓存而非重算

KV Cache 的解决思路非常朴素：**既然历史 token 的 K、V 每一轮都是完全相同的，那就把它们的值缓存下来，只计算新 token 的 K、V。**

于是，自回归生成变成了：

```
第 1 步：算 token_1 的 K、V → [缓存 KV_1]
第 2 步：只算 token_2 的 K、V → [缓存 KV_1, KV_2]，对 [KV_1, KV_2] 做注意力
第 3 步：只算 token_3 的 K、V → 缓存追加，对 [KV_1, KV_2, KV_3] 做注意力
...
```

每一步只需计算**新增 token** 的 K、V，历史部分直接复用缓存，注意力从「每次全量重算」降为「只算新 token」，计算复杂度从 `O(n²)` 降到 `O(n)`。

## KV Cache 的显存开销

KV Cache 的收益巨大，但代价是**显存**。缓存大小可以用下面的公式估算：

```
显存 = 2 × 层数 × 头数 × 头维度 × 序列长度 × 批大小 × 精度字节数
```

其中 `2` 表示 K 和 V 两份缓存，序列长度是**动态增长**的（每生成一个 token 就多占一点）。

举个直观的例子：一个 7B 模型，32 层、32 个头、头维度 128，若推理时序列长度达到 4096、精度为 FP16（2 字节），单条请求的 KV Cache 约为：

```
2 × 32 × 32 × 128 × 4096 × 1 × 2 = 2 GB
```

可以看到，当序列变长、并发请求增多时，KV Cache 甚至可能超过模型权重本身，成为显存的主要占用者。这也是为什么「显存管理」会成为推理优化的核心命题。

## 注意力结构的演进与省缓存

KV Cache 的显存压力催生了对注意力结构的改造，核心方向是**让多个头共享同一套 K、V**：

- **Multi-Head Attention（MHA）**：每个头独立拥有 K、V，缓存开销最大。
- **Multi-Query Attention（MQA）**：所有头共享一套 K、V，缓存缩到 1/头数，但可能损失一些表达力。
- **Grouped-Query Attention（GQA）**：折中方案，若干个头分为一组共享 K、V，兼顾速度与质量。LLaMA 2/3、Mistral 等大量模型采用。

从 MHA 到 GQA，本质上是用「缓存大小」换取「质量与速度」的平衡。

## 与 PagedAttention 的关系

KV Cache 解决了「算不重复」，但没解决「存得聪明」。传统做法按请求最大长度预留连续显存，导致碎片化。vLLM 的 **PagedAttention** 正是针对 KV Cache 的存储问题：把缓存切成固定大小的「页」，按需分配、逻辑映射，实现零碎片与跨请求共享。

两者配合，KV Cache 既省计算、又省显存，共同构成了现代高效推理的基础。

## 小结

- KV Cache 通过缓存历史 K/V，把每步注意力从全量重算降为增量计算，是自回归推理提速的基石。
- 它的代价是显存随序列长度线性增长，长文本与高并发场景下可能成为瓶颈。
- MQA/GQA 通过共享 K/V 头来压缩缓存，PagedAttention 则优化了缓存的分配与管理。

理解 KV Cache，是理解大模型推理性能与显存优化的第一步。
